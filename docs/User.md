# ВЕБ-СЕРВИС ДЛЯ АВТОМАТИЗИРОВАННОГО ДОКУМЕНТООБОРОТА ПРИЕМНО-СДАТОЧНЫХ ИСПЫТАНИЙ «АТМ-КОНСТРУКТОР»

## РУКОВОДСТВО ПОЛЬЗОВАТЕЛЯ

## 1. Введение

### 1.1. Область применения 
Веб-сервис предназначен для составления приемно-сдаточных испытаний (АТМ, далее – документы испытания) авиатренажера. 

### 1.2. Краткое описание возможностей 
Веб-сервис предоставляет следующие возможности: 
* Авторизация и регистрация пользователя.
* Разделение проектов на личные (для работы над ними самим пользователем) и общие (для просмотра наработок других пользователей).
* Возможность полностью передать личный проект со всеми ревизиями другому зарегистрированному пользователю.
* Создание документа испытаний под конкретные авиатренажеры с привязкой к международным кодам (ATA или FSTD) и автоматическим подбором названий систем и подсистем.
* Контроль текущего состояния АТМ через систему статусов (*Черновик, В работе, На проверке, Готово*).
* Быстрое наполнение документа путем перетаскивания готовых проверок и результатов из системной библиотеки.
* Фоновое автосохранение изменений раз в 5 минут для защиты от потери информации и предпросмотр всех разделов.
* Автоматическое наполнение полей титульного листа для области общих сведений, загрузка логотипов компаний.
* Заполнение полей компании и их сотрудников для листа согласования.
* Автоматическое копирование всех данных при создании новой ревизии документа и возможность просмотра старых версий без их редактирования.
* Экспорт готового структурированного файла формата `.docx` строго по отраслевому шаблону на выбранном языке (русском или английском).
* Управление через административную панель пользователями, справочниками, основной частью конструктора.

### 1.3. Уровень подготовки пользователей 
Пользователи веб-сервиса должны обладать следующими минимальными навыками для работы:
1. Навык составления документов испытаний для авиатренажера.
2. Уверенное владение современными интернет-браузерами, умение работать с современными операционными системами и сайтами.
3. Умение работать с загруженными файлами формата `.docx` для финальной проверки сгенерированных шаблонов.
4. Базовое понимание кодирования авиационных систем ATA / FSTD.

## 3. Описание операций 

### 3.1. Страница авторизации

При авторизации в систему на экране будет открыта форма. Для регистрации необходимо заполнить поля в окне «Регистрация»: ФИО, Логин, Пароль (можно просматривать введенный пароль, нажав на соответствующую иконку). По завершении нажать на кнопку «Создать аккаунт» (рис. 1). После этого в базе данных создастся новая учетная запись.

Рис. 1. Форма регистрации в веб-сервисе

Для того, чтобы совершить вход уже зарегистрированному пользователю в веб-сервис необходимо перейти в окно «Вход в систему» and заполнить поля: логин и пароль. По завершении нажать на кнопку «Войти» (рис. 2).

* Создать документ испытаний, нажав на поле создания.
* Переключить язык или выйти с сайта.
* Найти проект при помощи поля поиска сверху.

### 3.4. Страница редактора

Для того, чтобы перейти на страницу редактора необходимо нажать на кнопку «Посмотреть» (если проект чужой) или кнопку «Редактировать» (если этот проект создал пользователь). При переходе пользователь сразу же окажется на вкладке «Основная часть», где он сможет формировать основную часть документа, выбирая действия и проверки.

В верхней части страницы пользователю доступно:
* Кнопка «Назад» для перехода обратно на страницу документов испытаний.
* Указание названия системы, код и ревизия.
* Строчка автосохранения, сохраняющая документ испытаний каждые 5 минут.
* Переключатели вкладок для заполнения разделов.
* Смена статуса карточки.
* Кнопки сохранения и экспорта в Word (экспортирует сформированный документ).
* Переключение языка (рис. 16).

## 4. Ситуации, при которых возникают ошибки 

В веб-сервисе при возможности возникновении каких-либо конфликтных ситуаций предусмотрены специальные ошибки для того, чтобы их можно было избежать:

* При нажатии на кнопку входа без заполненных полей или если логин и пароль являются неправильными в форме входа возникает ошибка «Неверный логин или пароль».
* При нажатии на кнопку регистрации без заполненных или частично-заполненных полях в форме регистрации возникает ошибка – под незаполненными полями появляются надписи «Введите ФИО», «Введите логин» и «Введите пароль» соответственно. Если пароль не подходит условию - пароль должен содержать минимум 8 символов и латинские буквы (a-z) выскакивает ошибка с данным текстом.
* При создании нового проекта или документа испытания в модальном окне их создания если такой проект или документ испытаний уже существует возникнут ошибки - «Создать проект не получится. Такой проект уже есть» и «Создать АТМ не получится. Такой АТМ уже есть» соответственно.
* При передаче проекта в модальном окне если не заполнить поле логина возникнет ошибка - «Поле login обязательно для заполнения». Также если такого пользователя не существует возникнет ошибка - «Ошибка. Пользователь не найден».
